# Тест Джитси: искусственные участники (Playwright + Chromium)

Измеряем не генератор, а сервер: генератор — отдельная временная ВМ (16 vCPU / 16 ГБ, Ubuntu 22.04, та же зона, что и Jitsi), сервер — `tolk-jitsi` (`meet.tolkplace.ru`).

1. Генератор: `scp -r deploy/loadtest/jitsi ubuntu@<IP-генератора>:~/jitsi_load && ssh ... "cd ~/jitsi_load && chmod +x *.sh && ./setup_generator.sh"`.
2. Сервер Jitsi: на ВМ `tolk-jitsi` запустить `vm_load_monitor.sh` (пишет `load_log.csv` раз в 5 с: CPU контейнеров, память JVB, сеть, число конференций/участников из colibri).
3. Генератор, запуск сценария: `node jitsi_load.mjs --domain meet.tolkplace.ru --rooms 7 --per-room 2 --minutes 5 --p2p on` (затем `--p2p off`).
   Сценарии: 7 комнат (≈ бета, 20 психологов при ~35% одновременности), 20 комнат, 35 комнат (≈ 100 психологов). Между прогонами 2 минуты паузы.
4. Результаты: `jitsi_run_*.jsonl` на генераторе (подключения, комнаты с полным составом, число P2P-соединений, CPU генератора; прогон с `invalidGenerator=true` не считается) и `load_log.csv` на сервере.

Ограничения: фейковое видео Chromium 640x480@20 fps (реальные камеры/экраны дают другую нагрузку); все участники в одной сети с сервером — качество связи через интернет РФ не проверяется (только пропускная способность и CPU сервера); P2P между двумя Chromium на одной машине всегда находит прямой путь, то есть P2P-режим показывает нагрузку только на сигнализацию. Селекторы клиента Jitsi (`APP.conference`, `APP.store`) не проверены на конкретной версии образа до первого запуска.
